# 02 · 挖掘：从原始取样到 Token 候选

---

## 1. 命令

```bash
$NODE $FACTORY/scripts/mine-tokens.js \
  --online=list.json,form.json,detail.json \
  --figma=figma-vars.json \
  --grid=8 --min-count=2 \
  --out=mining-report.md \
  --emit-tokens=tokens.draft.md
```

| 参数 | 默认 | 说明 |
| :-- | :-- | :-- |
| `--online` | — | 采集 JSON，逗号分隔多份，会合并统计 |
| `--figma` | — | 设计稿导出，四种形态自动识别 |
| `--grid` | 8 | 期望网格基数，用于标注不合网格的间距 |
| `--min-count` | 2 | 出现次数低于此值不进候选（滤手滑值） |
| `--emit-tokens` | — | 额外产出 tokens.md 草稿表格 |
| `--json` | — | 输出机器可读 JSON |
| `--out` | stdout | 报告写文件 |

---

## 2. 输出怎么读

### 结构特征 → 该建哪些文档

脚本按类名/标签猜结构（侧边栏 / 顶栏 / 表格 / 表单 / 分页 / 浮层 / 图表 / 卡片 / 标签）。
猜得不准，但给的是**「有没有」**的信号，不是精确数量。

判读原则：**信号 > 0 就值得建文档，信号 = 0 就不要建。**
不存在的页面类型写了文档，只会让人照着做一个系统里根本没有的东西。

### 颜色候选

每行带 `次数` 与 `用途分布`（background-color / color / border-color）：

- `background-color` 第 1 高频 → 大概率页面底色
- `color` 第 1 高频 → 大概率正文色
- `border-color` 第 1 高频 → 大概率分割线色
- 非灰、用于背景、频次高但不是页面底 → **主色候选**

脚本会给语义初判，但一律标注「必须人工确认」。这个初判基于频次，
而频次和语义没有必然关系——辅助色可能比主色出现得还多。

### 间距候选与网格拟合

脚本取高频间距的**公约数**作为拟合网格基数：

- 拟合值 = 期望值（如 8）→ 网格规整
- 拟合值 ≠ 期望值 → **别急着改设计**，先确认是不是基线不同（有的系统是 4px 基线）

`不合 Npx 网格` 的清单要逐条看：可能是真的设计不规整，也可能是采集到了图标偏移、边框补偿这类
本来就不该进 Token 的值。

### 设计稿 ↔ 线上差异

| 差异 | 含义 | 怎么判 |
| :-- | :-- | :-- |
| **F1 设计稿有、线上无** | 设计稿超前，或设计稿虚胖 | 问设计师：这个变量实际用在哪？说不出来就是虚胖 |
| **F2 线上有、设计稿无** | 线上历史遗留色 | 问：收编进规范，还是线上整改？ |
| **匹配** | 两边一致 | 最可信的一批，优先定稿 |

**定哪边是意图源，再改另一边。禁止两边各留一个数。**

## 3. 命名规则

不能靠机器裁决语义，但命名格式要统一：

| 类别 | 格式 | 例 |
| :-- | :-- | :-- |
| 颜色 | `--color-<语义>[-<状态>]` | `--color-primary-hover` |
| 文本色 | `--color-text-<层级>` | `--color-text-tertiary` |
| 功能色 | `--color-<语义>-text` / `-bg` | `--color-error-bg` |
| 间距 | `--space-<数值>` | `--space-4`（=16px） |
| 字号 | `--font-size-<语义>` | `--font-size-body` |
| 圆角 | `--radius-<档位>` | `--radius-default` |
| 阴影 | `--shadow-<组件/语义>` | `--shadow-card` |
| 组件尺寸 | `--<组件>-<属性>` | `--floating-header-height` |

**语义命名优先于视觉命名。** `--color-primary` 而不是 `--color-blue`——
品牌色从蓝改绿时，前者改一处，后者要全库改名。

### 同值不同名不要合并

两个 Token 当前取值相同，不等于可以互换。功能色与涨跌色是典型：
现在都是红，但功能色会跟着告警语义走，涨跌色跟着境内惯例走，各自演进。
合并了，将来拆分时才知道有多痛。

---

## 4. 常见误判

| 现象 | 真因 | 处理 |
| :-- | :-- | :-- |
| 大量 `1px` 间距 | 边框宽度被当间距采了 | 看 props 过滤，或提高 `--min-count` |
| 出现十几种灰色 | 同一灰阶被不同透明度渲染 | 按透明度合并，或确认设计稿灰阶档位 |
| 主色候选是灰色 | 页面主色用得少、灰底铺得多 | 从设计稿补，别信频次 |
| 字号有 `13.5px` 这类碎值 | 浏览器缩放或继承计算 | 忽略，取整数档 |
| 阴影几十种 | 阴影被多处微调 | 归并成 3–5 档语义阴影 |

---

## 5. 输出物

- `mining-report.md` —— 给人和 Agent 看的完整报告
- `tokens.draft.md` —— 候选 Token 表格，**草稿，确认后并入 `foundation/tokens.md`**

草稿里的 Token 名是 `--color-candidate-N` 这种占位名，
必须逐个改成语义名才能转正。占位名进了规范，等于给全库埋了一颗叫 candidate 的雷。
