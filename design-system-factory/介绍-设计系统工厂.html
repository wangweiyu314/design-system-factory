Design System Factory · v1.0

设计系统工厂

给一套 Figma 设计规范和几个线上页面地址，产出一套可交付的中后台设计系统技能包： 规范文档 + HTML 模板 + Token 校验器 + 页面生成器 + 提交门禁。

输入：Figma + 线上页面 产出：同构技能包 含 3 个可执行脚本 2026-09-09

01它是干什么的

一句话：把「建一套设计系统」这件事，从手工作坊变成有流程、有校验、可复现的工程。

过去建一套设计系统技能包，要人工翻设计稿抄数值、对着线上页面核实现、手写二十份规范文档、 再做模板和校验脚本。整个过程没人知道抄错了没有——因为设计稿和规范里两个数「看起来都合理」。

这个工厂把流程固化成五阶段，把最容易出错的三件事交给脚本： 线上取值怎么拿、候选值怎么聚、前缀和规范骨架怎么建。 剩下的判断——哪个是主色、哪边是意图源——必须留给人。

关键立场：不生搬硬套。 标杆页、强约束清单、组件清单全部由对方系统的实际采集结果生成， 不复制任何既有系统的数值与规则。抄来的约束在新系统没验证过，等于没有。

02解决什么问题

三个真实存在的卡点，以及现在怎么处理。

线上页面抓不到
中后台基本都在内网、需要登录，自动化工具打不开，只能靠人肉截图描述。
取值抄错没人知道
设计稿到规范是人工转录。抄错不会报错，只会悄悄变成规范的一部分，几个月后才暴露。
规范写完落不了地
文档是一套、代码是另一套。没人记得跑校验，规范很快就和实现对不上。

对应做法

× 过去
人肉看截图描述颜色 → 凭感觉给主色命名 → 规范写完就结束，没有校验环节。
✓ 现在
浏览器采集真实 computed style → 频次聚合出候选、语义由人确认 → 校验器双向比对 + 提交门禁强制生效。

03五阶段流程

顺序不能乱，第 ③ 步不能跳过、不能由 AI 代劳。

1
采集 · Intake
Figma 变量（MCP 或导出文件）+ 线上页面 computed style。两条腿都要，缺一条就只能描述现状或空谈意图。
2
挖掘 · Mining
多页合并统计，产出 Token 候选、页面结构特征、设计稿↔线上差异（F1/F2）与存疑项。
3
裁决 · Adjudication　← 人工，不可跳过
机器能算出「#2A6CDD 出现了 47 次」，算不出「这是品牌主色」。语义命名猜错的代价远大于猜对的收益——一个错的主色会顺着模板扩散到几十个页面。
4
生成 · Generation
建包（引擎复制 + 类名前缀替换 + 系统名参数化）→ 填规范 → 补组件/页面文档 → 出标杆页。
5
校验 · Verify
双向 Token 校验退出码必须为 0；用 git 的仓库再装提交门禁，让约束自动生效而不是靠自觉。

04三个脚本（功能说明）

工厂里真正干活的部分，都经过实测。

collect-from-browser.js
解决内网需登录。发给能打开页面的人，在控制台粘贴运行， 自动导出 computed style JSON（颜色/字号/间距/圆角/阴影/关键尺寸/结构特征）。 只读 DOM，不发请求、不改页面、不碰登录态。
mine-tokens.js
取值挖掘。多页采集合并统计，输出 Token 候选、网格拟合覆盖率、 页面类型推断，以及设计稿↔线上差异 F1/F2。只给候选和存疑，不做命名裁决。
init-package.js
一键建包。复制引擎（4 个 JS + 11 套 HTML 模板 + 2 份说明）， 全量替换 CSS 类名前缀、系统名、环境变量名，并生成规范文档骨架。

你要准备什么，最后拿到什么。

环节输入产出
设计稿 Figma 文件（MCP 接入）／变量导出 JSON·CSV／截图 设计意图值，用于与线上实现做双向核对

06五分钟上手

复制即可跑，路径按实际环境调整。

# 0. 环境（版本目录带 -2 后缀，写错会 no such file）
NODE=/Users/<你>/.workbuddy-ai/binaries/node/versions/22.22.2-2/bin/node
FACTORY=/path/to/design-system-factory

# 1. 挖掘：线上采集 + 设计稿导出 → Token 候选与差异
$NODE $FACTORY/scripts/mine-tokens.js \
  --online=list-styles.json,form-styles.json,detail-styles.json \
  --figma=figma-vars.json \
  --out=mining-report.md --emit-tokens=tokens.draft.md

# 2. 建包：引擎复制 + 类名前缀替换 + 文档骨架
$NODE $FACTORY/scripts/init-package.js \
  --name=某某资管平台 --prefix=am --out=./am-design-specs

# 3. 填规范（人工）：先写 tokens.md，再回灌各模板 :root
#    顺序反了必然双源漂移

# 4. 校验：退出码必须是 0
$NODE am-design-specs/scripts/check-tokens.js . --strict
第 3 步没有捷径。 候选值必须经设计师确认才能定稿。草稿里的 Token 名是 --color-candidate-N 这类占位名， 转正时要逐个改成语义名——占位名进了规范，等于给全库埋一颗叫 candidate 的雷。

07产出的包里有什么

和既有设计系统包同构，但数值、页面类型、约束都来自你这套系统。

<prefix>-design-specs/ ├── SKILL.md 包内入口（文档路由 + 强约束清单） ├── foundation/ │ ├── tokens.md 取值唯一来源 │ └── design-sync.md 设计稿 ↔ 规范映射与同步流程 ├── components/ 只写实际存在的组件 ├── pages/ 只写实际存在的页面类型 ├── examples/ 标杆页 └── scripts/ ├── check-tokens.js Token 双向校验 ├── check-design-sync.js 设计稿 ↔ 规范核对（抓转录误差） ├── new-page.js 一键页面生成器 ├── install-hooks.js 提交门禁（不合规不让提交） └── <分类>/*.html 11 套已验证模板

五项校验到底查什么

项含义
E1 硬编码正文出现未在 :root 声明的色值字面量
E2 取值漂移文件 :root 定义与规范不一致（规范 → 交付物）
E3 未定义引用用了 var(--x) 但本文件没定义，引用即失效
W1 规范未收编交付物在定义和使用，规范里却没有（交付物 → 规范）
I1 规范未落地规范定义了但全库零使用，用于清理废 Token
只做单向校验不算数。 只查「交付物有没有按规范写」，会漏掉「规范没收编」的私有 Token—— 这类 Token 曾悄悄长到 58 个才被发现：模板里在用，规范里没有，谁也不知道该听谁的。

08它不做什么

边界说清楚，比吹能力有用。

不裁决语义命名
主色、成功、警告、错误这些语义必须有设计师确认。脚本只给频次排序。
不代劳登录态
内网页面不去硬闯。改由能打开页面的人跑采集脚本，交回 JSON。
不生成业务文案
标杆页只出骨架与规范样式，业务字段、数据、提交逻辑要逐项替换。
不预设页面类型
结构特征信号为 0 的页面类型不建文档，避免同事照着做一个系统里根本没有的页面。

常见问题

问答
一定要有 Figma 吗？不一定。但只有线上采集时，规范描述的是「现状」而非「意图」，历史遗留脏值会被洗白成标准。
线上页面一个都打不开？走人工标注：截图 + 填 examples/intake.sample.json。质量下降，但比硬编数值强。
能直接复制现成规范改改吗？不能也不该。数值与约束是特定系统的产物，在你这套里没验证过，等于没有。
校验通过就完事了？退出码 0 只是及格线。规范要跟着设计稿升级持续维护，见产出包的 foundation/design-sync.md。
